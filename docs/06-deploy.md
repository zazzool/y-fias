# Выкладка для теневой работы

Цель этой выкладки — **не** заменить что-либо в МИС, а начать неделю
наблюдения. Сервис работает рядом, его ответы игнорируются, расхождения
записываются. Прод при этом не меняется.

## Ресурсы

| Что | Сколько |
|---|---|
| Память в работе | ~131 МБ данные и индексы, плюс среда Go — считать **400–500 МБ** |
| Пик при старте | до 1 ГБ на несколько секунд, пока строятся индексы |
| Диск под данные | 52 МБ, плюс столько же под предыдущий справочник при обновлении |
| Время старта | ~4.5 с |
| Процессор | простаивает; всплеск на 3–4 с при сборке индексов |

Пик при старте существеннее среднего: если на сервере свободно меньше
гигабайта, сервис может не подняться, хотя в работе занимал бы вчетверо
меньше.

## Безопасность

**Аутентификации у сервиса НЕТ.** Это осознанно для теневого режима, но
накладывает жёсткое условие.

* Порт наружу **не публикуется**. В `docker-compose.yml` не должно быть
  секции `ports` — только `expose`, чтобы сервис был виден бэкенду МИС по
  имени и больше никому.
* Адрес вызова психиатрической неотложки — специальная категория
  персональных данных (152-ФЗ, ст. 10). В журнал `addr_events` попадает
  сырой ввод диспетчера, то есть адреса. База `yfias` подпадает под те же
  требования, что и `ponp`.
* Метрики (`/metrics`) содержат только счётчики без адресов, но лежат на том
  же порту и наружу тоже не выходят.

## Две строки подключения, и это не случайно

```
-dsn      postgres://yfias:***@postgres:5432/yfias    своя база, чтение и запись
-mis-dsn  postgres://ponp:***@postgres:5432/ponp      база МИС, ТОЛЬКО ЧТЕНИЕ
```

До этапа 5 таблица `addresses` принадлежит МИС. Разделение на уровне
конфигурации делает это правило видимым при выкладке, а не только в
комментарии к коду.

Пользователю для `-mis-dsn` достаточно `SELECT` на `addresses`. Если есть
возможность завести отдельную роль только с этим правом — лучше так:

```sql
CREATE ROLE yfias_reader LOGIN PASSWORD '***';
GRANT CONNECT ON DATABASE ponp TO yfias_reader;
GRANT USAGE ON SCHEMA public TO yfias_reader;
GRANT SELECT ON TABLE addresses TO yfias_reader;
```

На первой неделе `-mis-dsn` можно не задавать вовсе: сверка адресов нужна
синхронизации, а она выключена.

## Сервис в `docker-compose.yml` МИС

```yaml
  # Адресный сервис Y-FIAS. ТЕНЕВОЙ РЕЖИМ: ответы игнорируются.
  # Порт наружу не публикуется — аутентификации у сервиса нет.
  yfias:
    build:
      context: ../Y-fias
      dockerfile: Dockerfile
    restart: unless-stopped
    expose:
      - "8080"
    volumes:
      - yfias-data:/data:ro
    environment:
      TZ: Europe/Moscow
    command:
      - "-addr=:8080"
      - "-snapshot=/data/gar.yfsnap"
      - "-geo=/data/geo.json"
      - "-coords=/data/coords.yfcoord"
      - "-dsn=postgres://yfias:${YFIAS_DB_PASSWORD}@postgres:5432/yfias?sslmode=disable"
      # Синхронизация на первой неделе ВЫКЛЮЧЕНА: справочник свежий,
      # а лишняя движущаяся часть при наблюдении не нужна.
    depends_on:
      postgres:
        condition: service_healthy
    mem_limit: 1g
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://127.0.0.1:8080/readyz"]
      interval: 30s
      timeout: 5s
      start_period: 60s

volumes:
  yfias-data:
```

Бэкенд МИС получает `YFIAS_URL=http://yfias:8080`.

## Порядок выкладки

Собранные и проверенные файлы копируются, а не пересобираются на сервере:
так на прод попадает ровно то, что здесь проверено.

```bash
# 1. База
docker exec -i ponp-postgres psql -U postgres -c \
  "CREATE DATABASE yfias OWNER ponp"

# 2. Данные (52 МБ)
scp data/gar.yfsnap data/geo.json data/coords.yfcoord \
    root@СЕРВЕР:/tmp/yfias-data/

docker volume create yfias-data
docker run --rm -v yfias-data:/data -v /tmp/yfias-data:/src alpine \
  sh -c 'cp /src/* /data/ && ls -la /data'

# 3. Сборка и запуск
docker compose build yfias
docker compose up -d yfias

# 4. Проверка
docker compose exec yfias wget -qO- http://127.0.0.1:8080/healthz
```

Ожидаемый ответ:

```json
{"status":"ok","snapshot_version":20260818,"streets":85034,
 "houses":2344412,"areas":198,"weights_version":2}
```

## Что смотреть в первую неделю

Условие выхода одно: **`verdict="worse"` равно нулю.**

```bash
# Сравнения по классам
docker compose exec yfias wget -qO- http://127.0.0.1:8080/metrics \
  | grep yfias_shadow_verdicts

# Блокирующие расхождения поштучно
docker exec -i ponp-postgres psql -U ponp -d yfias -c "
SELECT raw_input,
       meta->>'reason'     AS причина,
       meta->>'legacy_top' AS прежняя,
       meta->>'ours_top'   AS наша
  FROM addr_events
 WHERE kind = 'shadow' AND meta->>'verdict' = 'worse'
 ORDER BY ts DESC LIMIT 50"
```

Кроме того:

* задержка адресных эндпоинтов МИС **не изменилась** — теневой вызов идёт без
  ожидания ответа и с таймаутом 50 мс, но проверить обязательно;
* `yfias_journal_dropped_total` близок к нулю (потери допустимы, но если их
  много — мал буфер);
* ни одного 5xx у основного бэкенда.

## Откат

Полный откат — одна команда, потому что прод ничего не отдавал Y-FIAS:

```bash
docker compose stop yfias
```

Со стороны МИС достаточно очистить `YFIAS_URL` — теневая отправка при пустом
значении не выполняется вовсе.

База `yfias` при этом остаётся; если нужно убрать и её:

```bash
docker exec -i ponp-postgres psql -U postgres -c "DROP DATABASE yfias"
```
